# Rebrand Planning

**Status:** Pending. As of **2026-05-17**, Dave is preparing to rebrand the company within a few weeks. The new name is **not yet finalized**.

## What lives here

- **`checklist.md`** — Every file, location, and asset that needs updating on rebrand day. Source of truth for the cutover.
- **`existing-posts-promotion-plan.md`** — Framework + schedule for promoting the 12 existing blog posts under the new brand's social handles (LinkedIn, Instagram, Facebook). Per-post copy gets drafted closer to each post's promotion slot.

## How to use this folder

- **Before the rebrand:** Add to the checklist as you discover more places that reference the old brand. Refine the promotion schedule as the rebrand date firms up.
- **On rebrand day:** Work through `checklist.md` top to bottom in a single branch. Open one PR with the full cutover so the deploy is atomic. Update memory entries and skill docs after the cutover.
- **After the rebrand:** Once `existing-posts-promotion-plan.md` is fully executed, delete this folder (or move it to an archive subfolder).

## For new content written between now and rebrand day

Default to the current brand (RO.bot / ro-bot.io / RO.blog) per `../../../shared/brand.md`. If a piece of content will publish very close to rebrand day, ask Dave whether to use the old name, the new name, or a placeholder. Do not pre-emptively switch to the new name without Dave's explicit go-ahead.
